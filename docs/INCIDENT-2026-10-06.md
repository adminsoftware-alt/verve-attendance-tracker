# Incident 2026-10-06: five rooms named "BREAK TIME", 25 people shown on break

## What happened
At 14:13 IST (the first Room Mapper panel run of the day, during lunch) one
sync named **25 rooms in one go**. Five different webhook rooms got
`8.0:BREAK TIME`; only one of them was the break room. Live merged them into
a single BREAK TIME card with 25 people, while Zoom showed those people in
1.18, 1.2, 1.5 and so on. Four work rooms also received a name that another
room already had (1.9, 1.24, 4.5, 6.0).

## Root causes (all pre-existing, now closed)
1. **Single-person naming shortcut.** The pending-request path (`/mapping/sync`
   "Resolved from sync payload" and the panel's `/mapping/resolve`) named a
   room from ONE person: "P joined webhook room U at 13:52; the panel now sees
   P in BREAK TIME, so U = BREAK TIME". No second witness, no check that P was
   still in U. At lunch P is in the break room, so P's team room gets the
   break room's name. Fix: `PENDING_SINGLE_WITNESS_RESOLUTION = False`. Every
   name must pass the witness rules (2 fresh / 3 total people agreeing).
2. **Nothing stopped one name being given to several rooms.** Fix: one name
   = one room. A name carried by an *occupied* room is refused for any other
   room, for first names and for corrections alike. When several rooms claim
   the same name in one sync only the best-supported one wins. An empty
   room's old name blocks nobody, so recreated rooms still get their names.
   Known trade-off: if two occupied rooms ever have their names swapped, the
   automatic correction stops and the Live pencil (room_overrides) fixes it.
3. **Corrections could not be saved.** The witness logic found the right name
   a minute later (`'8.0:BREAK TIME' -> '1.2:Between The Spreadsheet'`) but
   the BigQuery UPDATE failed on every sync: rows written by streaming cannot
   be updated for ~90 minutes. Fix: fall back to inserting a newer row; the
   builder prefers the most recent mapping.
4. **Live hid the problem.** Rooms were grouped by name, so five rooms looked
   like one. Fix: one card per occupied room id; a second id under the same
   name shows as `<name> [room 2]` with its own pencil. Empty duplicate ids
   are not shown.

no evidence which id is the real one, and the empty ids no longer show in

## Operating note
Run the panel at ~10:30, when people are settled in their rooms, not at lunch.
A lunch-time first run maximises the chance that "where is P now" and "which
room did P join" disagree. The panel ran for only three minutes today
(14:13-14:16); the witness logic needs it open for a few minutes to settle.
