## Two things that need a Cloud Run config change (run by a human)

Cloud Run configuration changes are not done from the assistant session; run
these once from your terminal.

### 1. Separate login-token secret
```powershell
$secret = -join ((1..48) | ForEach-Object { [char](Get-Random -InputObject (48..57 + 65..90 + 97..122)) })
gcloud run services update breakout-room-calibrator --region=us-central1 --project=verve-attendance-tracker --update-env-vars=AUTH_TOKEN_SECRET=$secret
```
Effect: everyone is logged out once (tokens re-signed); the startup warning disappears.

### 2. Move secrets into Secret Manager
Today the Zoom secrets are plain environment variables on the service (visible
to anyone who can `describe` it). Secret Manager keeps them out of the config:
```powershell
gcloud services enable secretmanager.googleapis.com --project=verve-attendance-tracker
foreach ($name in @('ZOOM_WEBHOOK_SECRET','ZOOM_CLIENT_SECRET','ZOOM_CLIENT_ID','ZOOM_ACCOUNT_ID','AUTH_TOKEN_SECRET')) {
  $value = Read-Host "Value for $name"
  $value | gcloud secrets create $name --data-file=- --project=verve-attendance-tracker
}
# let the service's runtime account read them
gcloud projects add-iam-policy-binding verve-attendance-tracker --member="serviceAccount:1073587167150-compute@developer.gserviceaccount.com" --role="roles/secretmanager.secretAccessor"
# mount as env vars (replaces the plain values) — one revision swap
gcloud run services update breakout-room-calibrator --region=us-central1 --project=verve-attendance-tracker --update-secrets=ZOOM_WEBHOOK_SECRET=ZOOM_WEBHOOK_SECRET:latest,ZOOM_CLIENT_SECRET=ZOOM_CLIENT_SECRET:latest,ZOOM_CLIENT_ID=ZOOM_CLIENT_ID:latest,ZOOM_ACCOUNT_ID=ZOOM_ACCOUNT_ID:latest,AUTH_TOKEN_SECRET=AUTH_TOKEN_SECRET:latest
```
No code change is needed: the app reads the same env var names.

## Endpoint audit (next step, needs a decision per endpoint)

About 100 of ~160 endpoints have no login check. Many are intentionally open
(webhook, Zoom-app panel, Cloud Scheduler callbacks, health). Others may not
need to be. List them:
```bash
grep -n "@app.route" app.py | grep -v -A0 "" | wc -l          # all routes
grep -n -A1 "@app.route" app.py | grep -B1 -v "require_auth" # routes without auth (manual read)
```
Recommended order: lock write endpoints (`POST/DELETE` under `/employees`,
`/teams`, `/data`, `/admin`, `/rooms`, `/debug`) first, verify the frontend
still works (it sends the token on every call), then review the GET ones.
